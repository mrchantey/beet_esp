# Alvik scenes

Each file here is a beet *scene*: a reflection-serialized slice of the ECS that
the `alvik-scene` firmware loads over HTTP to become its live API. A scene is
not config data, it *is* the robot's routes and behaviours. Send a different
scene and the same firmware exposes a different robot.

Send one with the controller (`examples/alvik/controller`):

```sh
cargo run -- load dance-routine    # POST scenes/dance-routine.json to /load
cargo run -- run dance-routine     # fire the action route it installed
cargo run -- clear                 # despawn it + reset
```

or with curl:

```sh
curl --data-binary @dance-routine.json -H 'content-type: application/json' \
     http://192.168.86.222:8080/load
```

The firmware also logs each canonical scene as JSON over defmt on boot, so these
files are regenerated by capturing that output (handy after changing a route
component). The entity ids in the files are placeholders, remapped on load; only
the `ChildOf` wiring between them matters.

## The scenes

- **rc.json** — the plain remote-control API: `drive/:dir` and `led/:side/:state`
  wired to the `DriveRoute` / `LedRoute` components. Equivalent to the hard-coded
  `alvik-rc` example, but sent over the wire.
- **dance-routine.json** — an *action route*: `dance-routine` runs a `Sequence`
  behaviour tree (forward 1s, left 1s, forward 1s, stop) via `ApplyDrive` +
  `EndInDuration`. Firing it returns immediately; the tree plays out on the async
  pool.
- **line-follower.json** — `line-follower` repeats a bang-bang `LineFollowStep`
  every 50 ms (forward on white, steer right on black).
- **roomba.json** — `roomba` repeats `RoombaStep`: cruise until the centre ToF
  sees a wall within 20 cm, then spin to clear it.
- **script.json** — `script` runs a **rhai program** (`AlvikScript`) every 100 ms:
  it reads an `AlvikInput` snapshot (depth, line, yaw, touch, elapsed) plus its
  own `state` array, and returns drive + LED + next `state`. Edit the `source`
  string to reprogram the robot with no reflash. Requires the firmware built with
  the `scripting` feature (`--features alvik,router,scripting`).
